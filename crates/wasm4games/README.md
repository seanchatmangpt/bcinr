# wasm4games

A branchless, `no_std`, engine-agnostic **game-pattern foundry** built on
[`bcinr-logic`](../bcinr-logic). Game behaviors — input admission, ticks, collision, combat,
status, physics, evidence, promotion — are expressed as **bounded byte-class state**
transformed by **branchless kernels** that reuse `bcinr-logic`'s verified primitives (masks,
saturating arithmetic, DFAs, popcount, permutation networks, rolling receipts).

Every meaningful transition can emit **object-centric process evidence**:

- `evidence::ocel` — object-centric events (OCEL-style): an activity, a logical timestamp, an
  admission status, and the real objects the event links to. Allocation-free by default;
  `OcelLog` + `to_json` are available under `alloc`.
- `evidence::otel` — 16-bit runtime span codes (no strings on hot paths).
- `evidence::receipt` — a tamper-evident rolling receipt chain (FNV-1a, via `bcinr-logic`).
- `evidence::replay` — deterministic replay frames for re-derivable digests.

## Doctrine

> **Engines project worlds; wasm4games operates patterns; wasm4pm admits evidence.**

wasm4games never decides admissibility itself. It *operates* patterns and *emits* candidate
evidence shaped to map 1:1 onto `wasm4pm-compat`. The authority that admits or refuses that
evidence is the external **wasm4pm** process miner.

## Kernels are generated, not hand-coded

The pattern kernels under `src/patterns/` and the `PATTERN_REGISTRY` are **generated by ggen**
from the input surface in [`ggen/`](./ggen) (the ontology `ggen/schema/patterns.ttl` is the
source of truth) and committed so the offline build never needs ggen. Do **not** hand-edit
generated kernels: edit the ggen input and regenerate. This is the **"GGEN-ONLY USER SURFACE"
covenant** — see the docs for the full rationale.

`src/ir.rs` is the single data model the ggen ontology mirrors, the generated registry is
built from, and `src/verify.rs` iterates over for offline self-checks.

## Offline commands

This crate builds and tests with no network access:

```bash
# Build (default is no_std, allocation-free)
cargo build -p wasm4games

# Test (std pulls in alloc + the test harness)
cargo test -p wasm4games --features std

# Lint — warnings are errors
cargo clippy -p wasm4games --all-targets --features std,bench -- -D warnings
```

### Feature flags

| Feature   | Effect                                                              |
| --------- | ------------------------------------------------------------------ |
| (default) | `no_std`, zero-alloc core.                                         |
| `alloc`   | Adds heap-backed types (e.g. `OcelLog`) and JSON export.           |
| `std`     | Implies `alloc`; enables `std` and the test harness.              |
| `bench`   | Pulls in Criterion for benchmarks.                                |

### wasm32

The crate is `wasm32`-ready. Build it with default features off (no `std`) for the browser /
WASM-4 fantasy-console target:

```bash
cargo build -p wasm4games --target wasm32-unknown-unknown --no-default-features
```

## wasm4pm is referenced, not vendored

The real admission bridge to **wasm4pm** lives in the workspace-**excluded**
`wasm4games-wasm4pm` crate, which is online-only (it depends on the upstream git repos and is
left out of the offline workspace build). This crate keeps only dependency-free *mirror* types
in `src/compat.rs`, shaped like `wasm4pm-compat`, so emitted evidence can be mapped 1:1 by that
bridge without pulling any git dependency into the offline build.

Upstream, referenced not vendored:

- wasm4pm — <https://github.com/seanchatmangpt/wasm4pm>
- wasm4pm-compat — <https://github.com/seanchatmangpt/wasm4pm-compat>
