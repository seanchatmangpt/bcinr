> **Owner:** `@hoare_oracle`

## 1. Axiomatic Mission & Scope

This specification defines the strict mathematical bounds for the **POWL Execution Dispatch Operator** ($f_{dispatch}$), which represents the final execution linkage in the Auto Select pipeline. It bridges the tape execution mask ($T_{mask}$) generated by the MAPE-K autonomic loop into the branchless POWL VM scheduler, ensuring the target workflow tape is fired exactly once per accepted transaction without invoking dynamic dispatch or `if`/`match` control flows.

## 2. Hoare Contract

Let $T_{mask} \in \{0, 2^{64}-1\}$ be the bounded target tape mask emitted by the MAPE-K loop, and $V_{state}$ be the current POWL VM scheduling state. Let $R_{tape}$ be the fixed-size ring or array of available tapes.

$$
\{ T_{mask} \in \text{TapeMask} \land V_{state} \in \text{PowlVmState} \land R_{tape} \in \text{TapeRegistry} \}
\quad f_{dispatch}(T_{mask}, V_{state}, R_{tape}) \quad
\{ V_{state}' \in \text{PowlVmState} \land E_{outcome} \in \text{DispatchReceipt} \}
$$

## 3. Definitional Bounds & Invariants

To comply with the BCINR Constitution (Rule 4), the primitive strictly enforces the following mathematical properties:

### A. Valid Input Domain
* $T_{mask}$: A 64-bit bounded mask identifying the scheduled tape(s). It is zeroed out if the proposal was rejected in previous loops.
* $V_{state}$: The deterministic state of the POWL engine (including `done_mask`, `choice_taken`, etc.).
* $R_{tape}$: The pre-loaded bounded set of Execution Tapes.

### B. Output Range
* $V_{state}'$: Deterministically updated POWL VM state advancing the execution scheduler.
* $E_{outcome}$: A branchless execution receipt indicating success or containing a typed refusal mask.

### C. Conservation Law
A single execution dispatch iteration fires operations exactly matching the intersection of $T_{mask}$ and the tape readiness predicates.
$$ \text{popcnt}(V_{state}'.\text{fired}) = \text{popcnt}(T_{mask} \land V_{state}.\text{ready}) $$

### D. Monotonicity Law
Within a single transaction, the VM state mutations (e.g., `done_mask`, loop iterators) mutate monotonically forward according to the execution mask calculus.

### E. Overflow Behavior
* Loop limits and iteration counters use strict branchless saturating arithmetic.

### F. Invalid-Input Refusal
Any invalid domain immediately projects into a failure mask ($M_{fire} = 0$), emitting a typed refusal:
* Tape mismatch $\rightarrow$ `ContractViolation` refusal.
* Rejection mask $\rightarrow$ Execution becomes a NO-OP, producing `ProposalRejected`.

### G. Determinism
* $CC=1$ across the entire transitive call graph.
* **Radon Law:** The instruction shape and timing remain constant regardless of whether $T_{mask}$ contains a valid tape dispatch or is completely zeroed out by a policy rejection. 

### H. State-Mutation Boundary
Adheres to Rule 10 (No mutation before complete admission). The updated VM state $V_{state}'$ is only committed using a fieldwise masked transaction over $T_{mask}$.
$$ V_{state}' = \operatorname{select}(T_{mask}, V_{candidate}, V_{state}) $$

### I. Numeric Error Envelope
* Mathematical bounds are exactly integer arithmetic with zero floating-point execution. $E = 0$.
