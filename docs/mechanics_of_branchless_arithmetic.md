# Mechanics of Branchless Arithmetic in BCINR

In the `bcinr` deterministic substrate, the **Radon Law ($CC=1$)** mandates that the authoritative hot path must be strictly branchless. Any data-dependent conditional branch (like `if`, `match`, or implicit JCC instructions generated by compilers) is an absolute violation of the project constitution. Branches introduce non-deterministic execution time due to pipeline flushes and branch mispredictions, breaking the fundamental requirement for constant-time, allocation-free algorithmic evaluation. 

To achieve $CC=1$, `bcinr` transforms sequential semantic decisions into parallel bitwise arithmetic—utilizing masks, XORs, and bit-shifts. This forces the compiler to emit straight-line code composed entirely of ALU operations (`AND`, `OR`, `XOR`, `NOT`, `SHR`) instead of `CMP` followed by `JCC` (Jump if Condition Is Met).

---

## 1. The Foundation: Canonical Masks

The core enabler of branchless execution is the **canonical mask**. Instead of using 1-bit boolean values (`true` or `false`), predicates in `bcinr` are evaluated to full-width bitmasks:
- **True:** All bits set (e.g., `0xFFFF_FFFF` for 32-bit operations).
- **False:** All bits clear (`0x0000_0000`).

Masks are generated via arithmetic rather than branching. For example, evaluating a less-than (`<`) relationship branchlessly in pure bit-parallel logic without native `<` operators involves exploiting the sign bit after wrapping subtraction. Alternatively, compiler intrinsics map cleanly to a branchless sequence like `SETB` + `NEG` on x86-64, emitting a full-width mask.

## 2. Conditional Addition (Masked Commits)

In traditional code, updating state based on a condition relies on a branch:
```rust
// Prohibited
if condition {
    a += b;
}
```

In the deterministic substrate, this violates the rule against speculative mutation and branches. Instead, `bcinr` enforces mask-based execution. 

To conditionally add `b` to `a`, the operation relies on a derived admission mask:
```rust
// Required
let mask = condition_mask; // 0xFFFFFFFF if condition met, 0x00000000 otherwise
a = a.wrapping_add(b & mask);
```
- If the mask is True (`0xFFFFFFFF`), `b & mask` equals `b`, and the addition proceeds.
- If the mask is False (`0x00000000`), `b & mask` equals `0`, and adding `0` leaves `a` unchanged.

This satisfies the requirement that the instruction shape remains fixed and independent of the input domain.

## 3. Branchless Min and Max (Multiplexing)

Evaluating minimums and maximums relies on unconditional evaluation of both operands, followed by a bitwise selection multiplexer.

```rust
pub const fn select_u32(mask: u32, a: u32, b: u32) -> u32 {
    // Branchless bitwise multiplexer
    (mask & a) | (!mask & b)
}

pub const fn min_u32(a: u32, b: u32) -> u32 {
    let mask = lt_mask_u32(a, b);
    select_u32(mask, a, b)
}
```

**Mathematical Context:**
$$ \min(a, b) = (\operatorname{mask} \land a) \lor (\neg \operatorname{mask} \land b) $$

- If `a < b`, the mask is `0xFFFFFFFF`. The expression simplifies to `(0xFFFFFFFF & a) | (0x00000000 & b) = a | 0 = a`.
- If `a >= b`, the mask is `0x00000000`. The expression simplifies to `(0x00000000 & a) | (0xFFFFFFFF & b) = 0 | b = b`.

Because both paths of the multiplexer are executed via ALU bitwise operations, no JCC instruction is generated. The execution work is perfectly bounded and static.

## 4. Branchless Absolute Value

To compute the absolute value of a signed integer without executing `if x < 0`, `bcinr` leverages two's complement arithmetic and arithmetic right shifts (`>>`).

```rust
pub fn branchless_abs_i32(x: i32) -> i32 {
    // 1. Replicate the sign bit across the entire word:
    // For positive x, mask = 0x00000000.
    // For negative x, mask = 0xFFFFFFFF (which is -1).
    let mask = x >> 31;
    
    // 2. XOR and Subtract:
    (x ^ mask).wrapping_sub(mask)
}
```

**Why it works:**
- **Positive `x`:** `(x ^ 0) - 0 = x`.
- **Negative `x`:** `(x ^ -1) - (-1)`. 
  - XORing with `-1` (all 1s) performs a bitwise NOT (one's complement).
  - Subtracting `-1` is identical to adding `1`, completing the two's complement transformation.

This completely bypasses the CPU's branch predictor. 

---

## Conclusion: Eliminating JCC Instructions

By treating conditional logic purely as bitwise polynomials, `bcinr` fulfills the requirements of the `@von_neumann_bypass` role: "Sequential semantic decisions must be transformed into masks; arithmetic selection; fixed lookup tables; generated straight-line code." 

JCC instructions require the processor to predict the outcome of a branch and speculatively execute it. If the prediction is incorrect, the pipeline is flushed—creating a timing side-channel. In a system managed under strict Hoare contracts by `@hoare_oracle` and structural gates by `@turing_machine`, the branchless paradigm ensures that every input takes precisely the same number of CPU cycles, preserving the Substrate Integrity Score (SIS) and achieving true deterministic stability.
