## Known, already-diagnosed sequencing blocker

`cargo package`/`cargo publish --dry-run` rewrite bcinr-cmca's path
dependency on bcinr-logic into a plain registry requirement
(`bcinr-logic = "^<version>"`). Until bcinr-logic at that exact version is
actually published to crates.io (or an equivalent registry the packaging
step is pointed at), that requirement cannot resolve and `cargo package -p
bcinr-cmca` fails with "failed to select a version for the requirement
`bcinr-logic = ...`" / "location searched: crates.io index". This script
detects exactly that error text and treats it as EXPECTED (non-gating);
any other failure is treated as UNEXPECTED and fails the gate. See
`docs/cmca-rdf/V26_7_17_RELEASE_LEDGER.md`'s "Publication Sequencing
Decision" section for the three lawful ways to resolve this.
