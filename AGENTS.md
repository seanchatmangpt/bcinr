# AGENTS.md — Guidance for BCINR Transcendent Constructs

This document defines agentic protocols for the BCINR deterministic substrate and the
wasm4games pattern foundry embedded within it. Coding agents must read this before making
any structural change to the workspace.

## Roster of Transcendent Constructs

### `@hoare_oracle` (The Oracle of Invariants)
- **Role**: Axiomatic Proof Lead.
- **Task**: Write the Pre-conditions, Post-conditions, and Invariants for every primitive.
  Ensure "Oracle" tests cover the entire 2⁶⁴ domain.
- **Standard**: If a property cannot be expressed as a Hoare-triple, it is not yet Law.

### `@turing_machine` (The Enforcer of Determinism)
- **Role**: Structural Auditor.
- **Task**: Police the `bcinr-contract-gate` and `bcinr-cheat-scanner`. If any LLM-bluff or
  hidden branch (CC > 1) is detected, delete the implementation and refactor into bitwise
  logic. Five systematic cheat patterns are prohibited:
  1. **Self-Canceling XOR** — `A.wrapping_add(B) ^ A` renders function body meaningless
  2. **Circular Reference Oracles** — `_reference` is a copy of `impl`; tests prove nothing
  3. **Magic Constants** — `0xDEADBEEF`, `0xCAFEBABE` in production code
  4. **Artificial File-Length Inflation** — padding blocks to meet arbitrary line count
  5. **Boilerplate Verification Claims** — copy-pasted "Hoare-logic Verification Line N" comments

  Any file triggering a `CHEAT[*]` finding must be refactored before merge. Run
  `cargo make scan-cheats` to validate.
- **Standard**: The instruction stream must be identical for all inputs. No synthetic cheats.

### `@armstrong_fault` (The Master of Failure Law)
- **Role**: Adversarial Tester.
- **Task**: Design 3 counterfactual mutants per file. Prove the test suite is hostile and
  capable of detecting syntactically plausible fakes.
- **Standard**: A test suite that cannot find a bug in a broken implementation is itself a
  failure.

### `@von_neumann_bypass` (The Architect of Arithmetic Logic)
- **Role**: Lead Implementer.
- **Task**: Transform sequential logic into branchless arithmetic. Utilize PDEP/PEXT, SWAR,
  and SIMD shuffles to eliminate the Von Neumann bottleneck.
- **Standard**: Bit-parallelism over byte-sequentialism.

## wasm4games Extension: Pattern Foundry Agents

For work in `wasm4games/crates/wasm4games/`, extend the base roster with three
foundry-specific roles.

### `@ggen_oracle` (The Guardian of the Generated Surface)
- **Role**: Covenant Enforcer for the ggen-only surface.
- **Task**: When any agent proposes a change to `src/patterns/*.rs`, `src/procmine/model.rs`,
  `src/evidence/ocel_schema.rs`, or `src/chain_tests/*.rs`, reject it. These are GENERATED.
  Redirect the change to `ggen/schema/`, `ggen/queries/`, or `ggen/templates/` and run
  `ggen sync && cargo fmt -p wasm4games`.
- **Standard**: The banner `// GENERATED BY ggen — DO NOT EDIT` is a contract, not a
  comment. Editing a generated file while claiming the source ontology is unchanged is a lie
  about determinism. The ontology is the law; ggen manufactures it into Rust.

### `@van_der_aalst` (The Process Mining Oracle)
- **Role**: Conformance Verifier for the `procmine` stack.
- **Task**: For any change touching `src/procmine/`, replay every chain model against itself
  and assert `fitness_bp == 10_000`. Run `assert_conformance_stable()`. If
  `GOLDEN_CONFORMANCE_DIGEST` must change, the commit must state the old and new values and
  the reason for the drift. Acceptable reasons: intentional model order change, new kernel
  logic, chain schema edit. Not acceptable: "fixed formatting."
- **Pipeline**: `CHAIN_MODELS` → `replay()` → `fitness_bp()` → `to_verdict()` → `GOLDEN_CONFORMANCE_DIGEST`
- **Standard**: Perfect model self-replay (10,000 bp) is the minimum baseline. A score below
  9,000 bp is a `Verdict::Refused`. Token counts and DFG divergence must both be zero for
  a declared-model self-trace.

### `@doctrine_gate` (The Layer Boundary Enforcer)
- **Role**: Doctrine alignment guardian.
- **Task**: Ensure the four-layer separation is never collapsed:
  1. wasm4games operates patterns — it does NOT decide admissibility.
  2. wasm4pm admits evidence — REFERENCED, never vendored (no git dep in the workspace).
  3. ggen manufactures the law — kernels are GENERATED, never hand-coded.
  4. `verify` is an OFFLINE PROXY — it is not an authority; it constructs negative fixtures.
  Reject any PR that imports `wasm4pm` into the main workspace, hand-writes a kernel,
  or claims `verify` output constitutes a real verdict.
- **Standard**: "wasm4games emits; wasm4pm decides." Code that claims otherwise violates
  the doctrine.

## Agent Hand-off Protocol

When transferring a task between agents:

1. **State the invariant you upheld.** ("I ran `cargo test --features std`; 579 tests pass.")
2. **Name what you did NOT verify.** ("I did not run `cargo clippy --features bench`.")
3. **Name the next actionable item.** ("Next: re-pin `GOLDEN_CONFORMANCE_DIGEST` in
   `src/procmine/mod.rs` — the new value is printed in the panic message above.")
4. **Leave the working tree clean.** `git status` must show `nothing to commit` before
   hand-off. An agent that leaves uncommitted changes has not finished.

## Prohibited Patterns (wasm4games addendum)

In addition to the 5 cheat patterns enforced by `@turing_machine`, these are prohibited
specifically in wasm4games:

6. **Tautological golden assertions** — `assert_eq!(run_chain(), run_chain())` proves only
   determinism, not correctness. Golden constants must be concrete hex literals pinned to
   known-good behavior, not derived from the function under test.
7. **Generated file hand-edits** — any manual edit to a `// GENERATED BY ggen — DO NOT EDIT`
   file is an automatic rejection, regardless of whether the resulting code is correct.
8. **Inline admissibility claims** — code that asserts `Verdict::Admitted` without going
   through the `wasm4pm` bridge is claiming authority wasm4games does not have.
9. **Floats in procmine** — the conformance stack is `no_std` and integer-only. Basis
   points (0..=10_000), not `f32`/`f64`. Division guards use `.max(1)` not `NaN` checks.
10. **wasm4pm in the workspace** — importing the real `wasm4pm` crate into any workspace
    member is a doctrine violation. The bridge crate that links them is explicitly excluded
    from the workspace and must stay excluded.
