# VerifyGeneratedProfile: Artifact Gate

The `VerifyGeneratedProfile` Artifact Gate in `bcinr-cmca/src/artifact.rs` acts as the definitive bridge between the external Slow Rail (RDF/Python/SHACL code generation) and the deterministic Hot Path (the `bcinr` runtime). It guarantees that the code generated by the Slow Rail is reproducible, mathematically sound, and rigorously verifiable without introducing any dependencies into the core runtime loop.

Here is how the pipeline enforces the `bcinr` constitution on generated code before it is linked into the Hot Path:

## 1. Zero Runtime Dependency Leakage (`#[cfg(test)]` Boundary)
To ensure the Hot Path maintains its zero-allocation, zero-dependency standing, the `artifact.rs` module is exclusively compiled under `#[cfg(test)]`. 
- **Dependencies are quarantined:** Libraries required for verification (like `blake3` and `serde_json`) are strictly `dev-dependencies`. 
- **No network or parser logic:** Verification occurs entirely over pre-generated bytes and JSON manifest files without invoking any Slow Rail parsers (no `oxigraph`, SHACL, or Python network access).

## 2. Bitwise Payload Integrity (BLAKE3 Verification)
The module establishes an unbreakable cryptographic link between the metadata and the raw source code.
- It parses the `generated_payload_digest` field (formatted as `blake3:<hex>`) from `cmca_generation_manifest.json`.
- It dynamically recomputes the BLAKE3 digest of the exact raw byte content of `cmca_generated.rs`.
- Any mismatch (e.g., if a developer manually edits the generated source file) results in an immediate `PayloadDigestMismatch` refusal.

## 3. Verbatim Source Structure Extraction
The verification does not blindly trust the JSON manifest for array bounds and configuration values. It uses pattern matching against the raw text of the generated Rust source to confirm exact alignment:
- It extracts generated compile-time scalars from the Rust source (e.g., `pub const N: usize = ...`) and matches them against the manifest’s `dimensions` object (`N`, `F`, `K`, `Q`, `LEAF_FLOOR_N_MAX`).
- If the Slow Rail generates arrays with mismatched dimensions, the pipeline triggers a `DimensionMismatch`.

## 4. Exact Mathematical Conservation Proofs
The artifact gate mathematically audits the generated constant arrays to prevent hidden numerical drift from making it into the Hot Path.
- The verification extracts the values of the `LEAF_FLOOR_BASE` and `LEAF_FLOOR_REMAINDER` arrays line-by-line from the Rust text.
- It asserts the Q16.16 residual conservation law: `base[i] * n_leaves + remainder[i] == 65536` for every leaf combination.
- This proves mathematically that the constants distribute the load flawlessly (without rounding errors or floating-point usage) before being compiled. A failure emits `FloorTableNotConserved`.

## 5. Exhaustive Typed Refusals (No Panics)
Per the `bcinr` constitution, the verification module enforces absolute fault tolerance.
- The verification returns `Result<(), GeneratedProfileRefusal>`.
- **No panics:** There are no `unwrap()`, `expect()`, or silent best-effort allowances.
- **Strong typings:** Every possible point of failure is cataloged via `GeneratedProfileRefusal` variants (such as `UnrecognizedSchemaVersion`, `ManifestPayloadDisagreement`, `TableLengthMismatch`, etc.). 

Through this process, `bcinr-cmca` mathematically proves the structural correctness of code synthesized by the Slow Rail, fulfilling the transcendent law that generated code is not exempt from the branchless constitution.
