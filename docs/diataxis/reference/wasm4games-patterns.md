# Reference: wasm4games Pattern Catalog

> Reference — the authoritative catalog of `wasm4games` patterns and the data model behind
> them. This mirrors `patterns::PATTERN_REGISTRY` (a `&[ir::PatternSpec]`). For the *why*,
> see the [foundry overview](../explanation/wasm4games-overview.md); to add an entry, see
> the [add-a-pattern tutorial](../tutorials/wasm4games-add-a-pattern.md).

## How to read this catalog

Every row is one `ir::PatternSpec`, which is itself a faithful projection of one
`w4g:Pattern` individual in `crates/wasm4games/ggen/schema/patterns.ttl`. The kernels are
**generated by ggen and committed**; they are never hand-written (see the
[GGEN-Only User Surface covenant](../explanation/ggen-only-user-surface.md)).

Columns:

- **Pattern** — PascalCase OCEL activity name (`EventKind::name`).
- **Kernel fn** — snake_case kernel function and generated file stem (`PatternSpec::name`).
- **Family** — the concern it belongs to (see [pattern families](#pattern-families)).
- **Lowering** — the branchless `ir::LoweringKind` the kernel reduces to, i.e. which
  `bcinr-logic` substrate it lowers onto.
- **Event code** — `EventKind::code` (`u16`), also the OCEL `event_code`.
- **Object kinds** — the `ir::ObjectKind`s the event links to (object-centricity).
- **OTEL span** — `PatternSpec::otel_span` (`u16`), matching `evidence::otel`.
- **Admission** — `required_status` ⇒ `refusal_status` from `ir::AdmissionRule`, using the
  [`class::status`](#the-classstatus-vocabulary) names.

> Note: numeric `event code` / `OTEL span` values below are the catalog's canonical
> assignments; the lifecycle span constants `TICK = 0x0001`, `INPUT_ADMIT = 0x0002`, and
> `RECEIPT_APPEND = 0x0003` are defined in `evidence::otel::span` and reused by the three
> lifecycle patterns. The exact bytes for each pattern are whatever the committed
> `PATTERN_REGISTRY` holds after `ggen sync`; treat this table as the declared intent that
> the ontology encodes.

## Pattern families

Families are a tag on the underlying `PatternSpec` data; they exist so the catalog can be
browsed, tested, and benchmarked by concern.

- **Core sim & combat** — input admission, fixed ticks, entity state machines, AABB
  collision resolution, damage application, and status effects.
- **Evidence & replay** — receipt appends, OCEL event linking, OTEL span emission, and
  deterministic replay-frame recording.
- **Physics & meaning** — physics-value rendering, semantic LOD selection, and projectile
  advancement.
- **Promotion & NPS** — mastery-moment detection, shareable-artifact generation, and
  NPS-prompt gating.

## Lowering kinds

`ir::LoweringKind` selects the branchless template and the `bcinr-logic` substrate a kernel
reduces to:

| `LoweringKind` | Substrate | Typical use |
|---|---|---|
| `Lut` | table-driven dispatch | classification, span selection, LOD tiers |
| `Mask` | `bcinr_logic::mask` (branchless select, `max_u32`) | admission gates, collision flags |
| `Saturating` | `bcinr_logic::int` / `fix` (saturating + clamp) | health, ticks, accumulators |
| `Bitset` | `bcinr_logic::bitset` (popcount, set ops) | mastery/skill flags |
| `Dfa` | `bcinr_logic::dfa` (deterministic transitions) | entity/AI/quest state machines |
| `Network` | `bcinr_logic::network` (sort/permutation networks) | ordering, deterministic shuffles |
| `Receipt` | `bcinr_logic::patterns::integrity_receipt` (FNV-1a) | receipts, replay digests, artifacts |

## The `class::status` vocabulary

The admission status alphabet (`class::status`) is a bounded `u8` lattice. Ordering is
meaningful: terminal/abnormal codes sort *above* the normal lifecycle so a worst-of join is
a branchless `max` (`Status::join`).

| Code | Name | Meaning |
|---|---|---|
| `0` | `UNKNOWN` | Nothing is known yet. |
| `1` | `BLOCKED` | A precondition prevented progress. |
| `2` | `PARTIAL` | Partially observed; not yet admissible. |
| `3` | `PENDING` | Awaiting a downstream decision. |
| `4` | `ADMITTED` | Admitted into bounded state. |
| `5` | `PROJECTED` | Projected to an engine/host surface. |
| `6` | `RECEIPTED` | Sealed into a receipt chain. |
| `7` | `REFUSED` | Refused by an admission rule. |
| `8` | `RESIDUAL` | Residual diagnostic preserved after repair. |
| `9` | `COUNT` | Cardinality of the vocabulary (not a status). |

`ByteClass::clamp(card)` corrals any `u8` into `[0, card)` via `bcinr_logic::fix::clamp_u32`
(a `card` of `0` is treated as `1`). `Status::join` computes the worst-of-code join via
`bcinr_logic::mask::max_u32`. The `compat::EvidenceState` lifecycle maps onto these codes:
`Raw → UNKNOWN`, `Parsed → PARTIAL`, `Admitted → ADMITTED`, `Projected → PROJECTED`,
`Exportable → PROJECTED`, `Receipted → RECEIPTED`.

## Evidence types

The four mirrored evidence channels (`evidence::*`), all shaped to map 1:1 onto
`wasm4pm-compat`:

### `OcelEvent` (`evidence::ocel`)

An object-centric event: an activity at a logical tick linked to real objects.

| Field | Type | Meaning |
|---|---|---|
| `event_code` | `u16` | Event-type code (matches `EventKind::code`). |
| `activity` | `u16` | The pattern id that produced the event. |
| `timestamp` | `u64` | Logical tick at which the event occurred. |
| `objects` | `ObjectRefs` | Bounded set of `(type_code, id)` links (CAP = 4). |
| `status` | `u8` | Admission `class::status` code at emission time. |

`OcelEvent` is `Copy` and allocation-free; `write_to` serializes it with a deterministic
big-endian encoding (a prerequisite for cross-host receipts). With the `alloc` feature,
`OcelLog` adds a growable stream and `to_json` (a hand-rolled, dependency-free
OCEL-flavored JSON array where every event carries its own `objects` links).

### `SpanCode` (`evidence::otel`)

A 16-bit runtime span code so hot paths never carry strings; names are resolved only at the
boundary. Canonical lifecycle codes live in `evidence::otel::span`: `TICK = 0x0001`,
`INPUT_ADMIT = 0x0002`, `RECEIPT_APPEND = 0x0003`. Each pattern's `otel_span` matches its
catalog row above.

### `ReceiptChain` (`evidence::receipt`)

A tamper-evident rolling receipt over emitted events, reusing
`bcinr_logic::patterns::integrity_receipt::DeterministicSubstrateReceipt` (FNV-1a). It is a
*telemetry* receipt (witnesses execution order so replays can be compared), not a
cryptographic signature.

| Member | Signature | Meaning |
|---|---|---|
| `new()` | `const fn -> ReceiptChain` | A fresh chain. |
| `append(&mut self, &OcelEvent)` | folds `event_code`, `status`, `timestamp` | Fold one event. |
| `count(&self)` | `-> u32` | Events folded so far. |
| `seal(&self)` | `-> u64` | Current rolling hash. |

`ReceiptEnvelope<const N>` seals a chain into a `Copy` `{ chain_hash: u64, count: u32 }`,
mirroring `wasm4pm-compat`'s `ReceiptChainConst<N>` / `ReceiptEnvelope` shape.

### `ReplayFrame` (`evidence::replay`)

One deterministic replay frame: an input applied at a tick and the resulting digest.

| Field | Type | Meaning |
|---|---|---|
| `tick` | `u64` | Logical tick. |
| `input` | `u64` | Admitted input word applied at this tick. |
| `state_digest` | `u64` | Digest of the resulting state. |

`verify::replay_digest` folds frames into a rolling digest; `verify::check_replay_determinism`
confirms that re-folding the same frames reproduces an identical digest — the property that
gives a replay evidentiary value.

## The `verify` self-checks (offline proxy)

`verify` is an *offline admissibility proxy*, **not** the authority (real admission is the
external `wasm4pm`'s job — see
[Run real wasm4pm admission](../how-to/wasm4games-run-wasm4pm-admission.md)):

| Function | Purpose |
|---|---|
| `check_status_bounds(spec, observed) -> bool` | `observed < status::COUNT`. |
| `replay_digest(frames) -> u64` | Fold replay frames into a rolling digest. |
| `check_replay_determinism(frames) -> bool` | Re-folding reproduces the same digest. |
| `negative_fixture(spec) -> OcelEvent` | An event stamped with `spec.admission.refusal_status` (and `activity = spec.id.0`) that a correct authority MUST refuse. |

These iterate `PATTERN_REGISTRY`, so every pattern in this catalog is checked
automatically.
