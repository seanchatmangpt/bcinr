# Rule 24: Substrate Integrity Score (SIS) Calculation & Mechanics

The **Substrate Integrity Score (SIS)** is the deterministic maturity metric defined in `AGENTS.md` (Rule 24). It mathematically reflects the completeness, rigor, and strict determinism of the codebase. A module must maintain a perfect score of 100/100 to achieve "PhD-Verified" status.

## 1. How SIS is Mechanically Computed
The repository constitution theoretically defines the SIS formula as subtractive:
`SIS = 100 - Σ (w_i * V_i)`

However, it is enforced **additively** in the CI pipeline by the `maturity_auditor.py` script (called via `audit_all.sh`). The auditor assigns points across four 25-point pillars:
1. **Determinism (25 pts):** Zero jump control flow (JCC). It parses the file and deducts these points if keywords like `if`, `match`, `while`, or `loop` are found in public functions.
2. **Behavioral Oracle (25 pts):** Explicit presence of a reference model (e.g., `_reference` or `_oracle`) and boundary tests (`boundaries`).
3. **Mutation Hostility (25 pts):** Requires at least 3 counterfactual mutants (`fn mutant_`) and 3 robust assertions of refusal/rejection.
4. **Axiomatic Proofs (25 pts):** Requires axiomatic or Hoare-logic documentation and enforces a minimum file length of 100 lines.

## 2. Where Violation Weights (`w_i`) Are Defined
As documented in `docs/sis_violation_weights.md`, **the repository does not currently tabulate explicit, distinct numerical weights (`w_i`) for non-absolute violations.**

Because the constitution mandates that only a perfect `100/100` is admissible, any non-absolute violation functionally acts as a strict blocking gate. A single missing requirement immediately drops the score below 100, which triggers the `MaturityScrutiny` protocol. Thus, explicitly defining varied weights is unnecessary since any deduction is fatal.

## 3. How Absolute Failures Force `SIS = 0`
The constitution defines a subset of constitutional violations—such as hidden authoritative branches, hot-path allocations, circular oracles, and scanner evasion—as **absolute failures**. These bypass the weighted average completely and force `SIS = 0`.

This absolute zero is **mechanically enforced by `tools/bcinr-cheat-scanner/src/main.rs`**. 
The cheat scanner traverses the codebase performing deep Abstract Syntax Tree (AST) and text-level inspections for Anti-Cheat rules (e.g., CHEAT-002: Circular Oracles, CHEAT-006: Scanner Evasion, CHEAT-020: Mutation before Admission). 

If the cheat scanner detects any absolute failures:
1. It immediately aborts the CI pipeline (`process::exit(1)`).
2. It overrides any partial score generated by `maturity_auditor.py`.
3. It immediately triggers the **MaturityScrutiny Protocol**, which freezes feature development, quarantines the code, and mandates a strict 9-step root-cause repair process before development can resume.
