# bcinr v2030.1.1 — PRD / ARD

**Repository:** `seanchatmangpt/bcinr`  
**Ecosystem role:** CMCA / deterministic computational kernel  
**Release:** Chatman Ecosystem v2030.1.1  
**Standing conferred:** `UNKNOWN`.

## Product requirement

`bcinr` SHALL remain the bounded deterministic substrate for computations whose authoritative execution must have fixed structural cost and independently verifiable semantics. Its v2030.1.1 role is to provide a small trusted mechanics layer beneath orchestration and autonomous systems—not to absorb rich semantic search that belongs upstream.

Governing principle:

> **Rich semantics upstream. Fixed deterministic mechanics downstream.**

## Required capabilities

1. Preserve bounded fixed-width input/output contracts for authoritative primitives.
2. Preserve repository constitutional runtime laws: `no_std`, no heap allocation, no data-dependent branching/termination, no panic/unwind paths, no floating point where excluded, no dynamic dispatch/indirect authority path, and fixed bounded work for authoritative execution.
3. Require a mathematical contract for each primitive: domain, range, invariants, overflow/error behavior, refusal conditions, determinism, and state boundary.
4. Pair authoritative implementations with independent oracle/proof evidence and hostile mutants.
5. Verify both source-level structure and object-code behavior where the claim requires instruction-shape guarantees.
6. Emit deterministic evidence/receipts sufficient for MFW and other consumers to bind exact kernel identities.
7. Refuse unsupported or structurally unlawful operations rather than silently falling back to a more dynamic implementation.

## Architecture requirements

```text
admitted fixed-width input
      -> mathematical contract
      -> structurally lawful implementation
      -> independent oracle / proof
      -> hostile mutation court
      -> source + object verification
      -> reproducible kernel evidence
```

The kernel SHALL NOT perform runtime ontology traversal, open-ended planning, variable graph search, or policy selection. Those are upstream responsibilities. BCINR executes admitted mechanics only.

## Acceptance for v2030.1.1

Each authoritative primitive must have:

- an exact mathematical contract;
- structurally lawful source;
- an independent oracle or proof;
- at least the repository-required hostile mutant coverage;
- source-level verification;
- object-code verification where applicable;
- reproducible evidence bound to the exact subject.

The ecosystem integration target additionally requires that MFW can pin BCINR kernel identity and distinguish kernel admission/execution evidence from orchestration or actuation evidence.

## Falsifiers

The architecture is falsified if a supposedly fixed primitive contains input-dependent control flow in authoritative object code; if tests can pass without detecting meaningful mutants; if runtime search is introduced to recover semantics that should have been admitted upstream; or if a kernel result is treated as authorization to actuate.

## Ecosystem contract

`bcinr` supplies deterministic mechanics. `mfw` orchestrates admitted consequences around those mechanics. Semantic reasoning, planning, policy, and BRCE authority remain separate. Passing kernel verification proves the kernel claim only.
