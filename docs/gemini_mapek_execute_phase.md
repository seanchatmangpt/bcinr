# The "Execute" Phase: Constant-Time Transitions in BCINR

In the BCINR Deterministic Substrate, the **MAPE-K Autonomic Loop** (Monitor-Analyze-Plan-Execute over a shared Knowledge base) manages autonomous decision-making. 

According to `GEMINI.md` and the project constitution (`AGENTS.md`), the core runtime laws dictate zero heap allocations (`#![no_std]`) and strict branchlessness (The Radon Law: $CC=1$). The 5th and final phase of the loop, **Execute**, mandates that the system must **"advance state via constant-time transitions."**

Here is exactly how BCINR achieves state transitions without any data-dependent branching (no `if`, `match`, or runtime loops):

## 1. Mask-Based Execution Law
Conventional systems use conditional logic to apply state changes (e.g., `if admitted { commit() } else { rollback() }`). In BCINR, this is illegal because it introduces branching, causing CPU pipeline mispredictions and timing side-channels.

Instead, BCINR leverages **Mask Calculus**. During the "Accept" phase (`PolicyGuard`), runtime predicates are reduced to full-width bitmasks ($m \in \{0, 2^w - 1\}$):
* **All-ones** (`0xFFFFFFFF`): The operation is accepted.
* **All-zeros** (`0x00000000`): The operation is rejected.

The state is then advanced using constant-time mathematical selection, defined universally as:
$$ \operatorname{select}(m, a, b) = (m \land a) \lor (\neg m \land b) $$

## 2. The Branchless Transaction Shape
Persistent state is never mutated speculatively. The "Execute" phase uses a rigid, allocation-free transactional shape:

1. **Copy:** The current immutable state ($x_t$) is copied into a fixed-size stack/scratch value.
2. **Derive:** The system structurally computes the candidate state ($x_{\text{candidate}}$) unconditionally.
3. **Commit:** A fieldwise masked commit is applied unconditionally using the admission mask ($m_{\text{admitted}}$) generated by the `PolicyGuard`.

The lawful mathematical equation for this commit is:
$$ x_{t+1} = \operatorname{select}(m_{\text{admitted}}, x_{\text{candidate}}, x_t) $$

## 3. Concrete Rust Implementation
Under the hood, this relies on primitives from `bcinr_logic::mask`. A selection is computed using pure bitwise arithmetic, enforcing the exact same instruction sequence regardless of the outcome:

```rust
#[inline(always)]
pub const fn select_u32(mask: u32, a: u32, b: u32) -> u32 {
    (mask & a) | (!mask & b)
}
```

State fields are updated individually through this function. If the operation is rejected, `mask` equals `0x00000000`. The expression `(0 & a) | (!0 & b)` resolves exactly back to `b` (the original state). 

## Summary
By using mask-based selection, an autonomic action that is rejected evaluates identically to the current state. **The rejected transaction runs through the exact same instruction sequence, cycles, and timing profile as an accepted one, leaving the persistent state bit-for-bit unchanged.** This completely eliminates timing side-channels and honors the "hard substrate" mandate of BCINR.
