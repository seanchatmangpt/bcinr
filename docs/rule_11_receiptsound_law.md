# Rule 11: The ReceiptSound Law

The ReceiptSound law governs the strict mathematical and structural preconditions required for adaptive mutation within the deterministic substrate. It establishes that adaptive state cannot be mutated speculatively or without complete, verifiable proof of validity.

## Required Logical Conjuncts for Adaptive Mutation

Adaptive mutation requires the absolute logical conjunction ($\land$) of five mandatory proofs. No alternate constructor or API is permitted to exist or bypass these conjuncts:

1. $\operatorname{AdmittedControlState}$: The operation's control state must be formally verified and admitted.
2. $\operatorname{AcceptedCertificate}$: A valid cryptographic or mathematical certificate (e.g., proving static domination or boundedness) must be accepted.
3. $\operatorname{AcceptedEnvelopeReceipt}$: Proof that the input/execution resides perfectly within the prescribed operational and numerical envelope.
4. $\operatorname{AcceptedOutcomeReceipt}$: Proof of a valid outcome generated by the preceding deterministic transition.
5. $\operatorname{CertifiedLearningMode}$: An explicitly certified mode that authorizes the adaptation of state weights or policies.

## Frozen Learning Behavior

The law explicitly mandates that **selection and learning are separate authorities**. When learning is frozen (e.g., when the `CertifiedLearningMode` conjunct evaluates to false), the system must fallback gracefully without violating the Radon Law ($CC=1$):

* **Deterministic selection may continue:** The system remains operational and can continue to make selections based on existing certified states.
* **All adaptive state fields remain unchanged:** Bit-for-bit immutability is enforced for persistent adaptive state.
* **Receipts may continue to accumulate:** The system continues to gather receipts and telemetric evidence for the MAPE-K loop.
* **No automatic recertification occurs in the hot path:** Recertification is strictly relegated to the slow rail and cannot happen implicitly during hot-path execution.

### The Mask-Based Fallback Requirement

In strict adherence to the project's branchless mandate, the frozen fallback must **not** be implemented using control flow branches (`if learning_frozen { ... }`). 

Instead, the fallback must be implemented via **masked state selection**. A full-width mask must be derived from the learning mode predicate, and a fieldwise bitwise `select` operation (e.g., $(m \land a) \lor (\neg m \land b)$) must be used to ensure that the unmutated current state is deterministicly selected when learning is frozen.
