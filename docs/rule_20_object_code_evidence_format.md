Here is the research on Rule 20 (Object-code audit) from `AGENTS.md` and the detailed explanation of the "Permitted evidence format" table.

According to Rule 20, every supported release target requires an exact production-profile disassembly audit. Since a source-level `CC=1` (Cyclomatic Complexity of 1) is necessary but insufficient to guarantee branchless execution, the audit must list each authoritative root and transitive helper symbol individually based on the final machine code. Any unclassified authoritative symbol blocks the merge.

The permitted evidence format is a table structured as follows:

| Symbol            | CC | Conditional jumps | Loop backedges | Panic path | Allocator | Standing |
| ----------------- | -: | ----------------: | -------------: | ---------: | --------: | -------- |
| `cmca_allocate`   |  1 |                 0 |              0 |         No |        No | ALIVE    |

### Column Breakdown and Requirements

*   **`Symbol`**
    *   **Represents**: The specific machine-code symbol (authoritative root symbol or transitive helper) being inspected in the disassembly.
    *   **Requires**: Every relevant function or symbol must be listed explicitly. If an authoritative symbol is missing or unclassified, it is a constitutional violation.
*   **`CC` (Cyclomatic Complexity)**
    *   **Represents**: The complexity score of the compiled function.
    *   **Requires**: Must be exactly `1`. Logic must be expressed as bitwise polynomials or straight-line code, without any branching.
*   **`Conditional jumps`**
    *   **Represents**: The presence of any input-dependent conditional branch instructions generated by the compiler.
    *   **Requires**: Must be `0`. The authoritative instruction shape must not depend on semantic input (no `if`, `match`, or hidden branches).
*   **`Loop backedges`**
    *   **Represents**: Backward jumps in the object code that indicate runtime or dynamic looping.
    *   **Requires**: Must be `0`. Unbounded execution is prohibited; any loops must be compile-time fixed, fully unrolled, or macro-generated without runtime iteration.
*   **`Panic path`**
    *   **Represents**: Whether the symbol can reach any panic handlers, unwinding routines, or bounds-check panics.
    *   **Requires**: Must be `No`. Authoritative code must safely handle domain limits via typed refusals rather than panics.
*   **`Allocator`**
    *   **Represents**: Whether any heap allocation symbols (e.g., `malloc`, dynamic memory growth) are reachable.
    *   **Requires**: Must be `No`. Hot-path execution must have a zero heap allocation boundary and operate in a `#![no_std]` context.
*   **`Standing`**
    *   **Represents**: The formal validation status of the symbol based on the repository's strict standing vocabulary (e.g., `ALIVE` or `BRANCHLESS_ALIVE`).
    *   **Requires**: A valid, bounded standing label that verifies the symbol has successfully passed all of the stated structural object-code gates.
