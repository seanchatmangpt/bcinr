# Transitive Call-Graph Branchlessness (Rule 7)

## Why Verifying the Public Entry Point is Insufficient
In the BCINR substrate, branchlessness is an absolute runtime law and a mathematical guarantee, not merely a superficial syntactical preference. Verifying only the public entry point creates an illusion of compliance—a "branchless wrapper" around branching logic—which fails to uphold the substrate's core mandate of fixed bounded execution work and zero timing variance. The objective is to achieve a cyclomatic complexity of exactly 1 ($CC=1$) for the *entire* runtime execution path. If any function deep within the call chain contains an input-dependent branch, the entire operation inherits that timing variance and structural unpredictability, violating the constitution of deterministic mechanics.

## Where Branches Hide
Branches are notorious for creeping into seemingly branchless code through language abstractions and compiler transformations. An audit must explicitly seek them out in the following constructs:

### Transitive Callees
A public function may structurally appear to have $CC=1$, but if it calls a private helper function, utility, or dependency that contains an `if`, `match`, or implicit branch (like `Option`-based control flow), the branchlessness guarantee is broken. The $CC=1$ rule applies transitively down the entire call tree, including private wrappers, fixed-point helpers, and serialization utilities reachable at runtime.

### Trait Methods
Rust's trait system can conceal branching logic behind clean abstractions. Even statically dispatched trait methods might contain complex control flow (e.g., fallback logic, bounds checks, or state-dependent behavior) within a specific type's implementation. A trait method call cannot be assumed safe without auditing the specific monomorphized implementation.

### Generic Monomorphizations
When generic functions are instantiated with specific types at compile time, the resulting machine code may differ significantly from the generic source. Type-specific implementations (e.g., specialized arithmetic, custom traits, or even implicit bounds checks on generic types) might introduce branches that were completely invisible in the abstract generic definition. 

### Macros
Macros expand into code that can be vastly more complex than their invocation site. Standard macros or custom `derive` macros often inject conditional checks, implicit control structures, or language-generated panic paths. For example, boundary checks or early returns generated by a macro will introduce conditional jumps in the resulting object code. The audit must always inspect the parsed expanded syntax tree, never just the source macro invocation.

### Compiler Intrinsics
Compilers may lower seemingly simple operations into branching instructions depending on the target architecture. For instance, specific integer division routines or complex bitwise operations on unsupported hardware might be lowered into runtime library calls or compiler intrinsics that rely on branching algorithms. What appears as a single branchless operation in Rust source code can become a branching loop in the emitted object code.

## The Required Audit Trace
Source claims do not substitute for disassembly evidence. To prove compliance with Rule 7, a full object-code audit trace must be produced for every supported release target. 

The prohibited claim is:
> "The function contains no `if`, therefore it is branchless."

The permitted claim is:
> "The full authoritative call graph contains no input-dependent conditional branch in the audited release object code for the declared target."

The required audit trace must explicitly map and document the transitive closure:
1. **Root function**
2. **→ Direct callees**
3. **→ Transitive callees** (including private functions, generated modules, indexing operations)
4. **→ Compiler intrinsics**
5. **→ Linked runtime symbols** (including language-generated panic paths)

The final audit result must provide a matrix listing each symbol individually, verifying:
- $CC=1$
- 0 conditional jumps
- 0 loop backedges
- 0 panic paths
- 0 allocator symbols

Any unclassified authoritative symbol in the object code blocks merge.
