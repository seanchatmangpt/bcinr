# BCINR v26.7.28 — Manufactured Temporal Runtime

## Release objective

v26.7.28 composes the existing temporal PDDL planner, POWL projection, Prolog8 admission gate, OCEL evidence model, and BLAKE3 receipt chain into one production boundary.

The release does **not** introduce an agent framework and performs **zero LLM calls**. Deterministic workers and hostile worker fixtures are used as executable system scenarios.

## Law-state path

```text
untrusted PDDL observation
  → parse and ground
  → temporal plan or typed planning refusal
  → grounded duration and identity admission
  → POWL temporal geometry
  → Prolog8 step admission
  → deterministic logical-time OCEL evidence
  → BLAKE3 execution root
  → replay verification
```

## ggen manufacturing boundary

The semantic source is owned by ggen PR #495. ggen manufactures:

- the stable Rust runtime profile;
- append-only language-neutral refusal codes;
- the deterministic scenario inventory;
- the C ABI contract;
- the WebAssembly Component Model contract;
- JSON conformance vectors.

BCINR imports those exact generated bytes through its dedicated manufacturer. The workflow reruns ggen and compares every imported output byte-for-byte. Generated outputs are not manually maintained.

## Executable scenarios

The manufactured inventory contains ten scenarios:

1. parallel software delivery;
2. dynamic team formation;
3. worker substitution;
4. shared accelerator contention;
5. deadline-aware verification;
6. long-running lease supervision;
7. speculative execution with exactly one commit;
8. adversarial worker refusal;
9. bounded approval before actuation;
10. distributed trace reconstruction.

Each scenario emits a deterministic event sequence, a typed terminal standing, and a BLAKE3 receipt that must replay.

## Temporal production claims

The production boundary admits only plans that satisfy the following bounded checks:

- finite non-negative start times, durations, and makespan;
- a maximum of 64 temporal operations;
- exact grounded action identity;
- duration inside the grounded action envelope;
- no overlapping duplicate instance of the same grounded action;
- one POWL operation per temporal step;
- exact POWL logical-time metadata;
- one OCEL event per temporal step;
- a reached final goal;
- a reproducible execution root.

## Exclusions

This release does not claim:

- distributed consensus;
- globally synchronized physical clocks;
- continuous numeric integration;
- probabilistic scheduling;
- unbounded temporal optimization;
- BRCE external actuation performance;
- AutoSelect or full MAPE-K closure.

These remain separate rails. Their absence does not collapse the bounded temporal production claim.

## Verification ladder

The exact-head manufacturer executes:

```text

  → rustfmt
  → cargo check
  → clippy -D warnings
  → temporal PDDL integration tests
  → all manufactured swarm scenarios
  → replay/tamper tests
  → Divan benchmark compilation
```

The release remains `PARTIAL_ALIVE` until the exact PR head completes the full ladder. Source publication or generation alone does not establish `ALIVE`.
